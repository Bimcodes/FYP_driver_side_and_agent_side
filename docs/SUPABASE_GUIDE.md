# Supabase Guide — QR Fare Transit App

This guide documents everything about how the Flutter app communicates with Supabase: the database schema, authentication, real-time streaming, GPS telemetry, and Row Level Security.

---

## What Is Supabase?

Supabase is a Backend-as-a-Service (BaaS) that gives us a hosted PostgreSQL database, an authentication system, and WebSocket-based real-time event streaming — without writing or hosting a backend server.

In this project, Supabase replaces:
- A REST API server → Supabase's auto-generated PostgREST API
- A JWT auth system → Supabase Auth
- WebSocket event broadcasting → Supabase Realtime
- A PostgreSQL installation → Supabase's hosted database

## Project Configuration

### Credentials Location

The Supabase URL and anon key are stored in:

```
lib/core/network/supabase_client.dart
```

The `initSupabase()` function is called at app startup in `main.dart` before any widget renders.

```dart
// lib/core/network/supabase_client.dart
const String _supabaseUrl = 'https://YOUR_PROJECT_ID.supabase.co';
const String _supabaseAnonKey = 'eyJ...your_anon_key...';

Future<void> initSupabase() async {
  await Supabase.initialize(url: _supabaseUrl, anonKey: _supabaseAnonKey);
}
```

> **Why is the anon key safe in the app?**
> The anon key is a *public* key — it identifies the project but grants no admin access. All data access is controlled by **Row Level Security (RLS) policies** that filter what each authenticated user can see or modify. The `service_role` key (which bypasses RLS) must **never** be embedded in the app.

### Supabase Client Provider

The `SupabaseClient` is exposed as a Riverpod provider so all Repositories can access it:

```dart
final supabaseClientProvider = Provider<SupabaseClient>((ref) {
  return Supabase.instance.client;
});
```

Every Repository reads this provider via its constructor:
```dart
class WalletRepository {
  final SupabaseClient _client;
  WalletRepository(this._client);
}

final walletRepositoryProvider = Provider<WalletRepository>((ref) {
  return WalletRepository(ref.read(supabaseClientProvider));
});
```

## Database Schema

### Tables

#### `users`
Stores one profile row per system user, linked to Supabase Auth by UUID.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | **Primary key.** Must match the Supabase Auth user's UUID exactly. |
| `role` | `TEXT` | `'Admin'`, `'Agent'`, `'Student'`, `'Driver'` |
| `name` | `TEXT` | Display name (e.g. `'Campus Gate Agent (John)'`) |

#### `wallets`
One wallet per user. Stores the current token balance.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key |
| `owner_id` | `UUID` | Foreign key → `users.id` |
| `wallet_type` | `TEXT` | `'Treasury'`, `'Agent_Vault'`, `'Student_Wallet'`, `'Bus_Vault'` |
| `balance` | `DOUBLE PRECISION` | Current token balance |

**Wallet types used in this app:**
- **Agent** users have an `Agent_Vault` wallet
- **Driver** users have a `Bus_Vault` wallet

#### `transactions`
Immutable double-entry ledger. Every token movement creates one row here.

| Column | Type | Notes |
|---|---|---|
| `id` | `UUID` | Primary key |
| `type` | `TEXT` | `'MINT'`, `'WHOLESALE'`, `'FARE'`, `'BURN'` |
| `sender_wallet_id` | `UUID` | Nullable — null for MINT (tokens created from nothing) |
| `receiver_wallet_id` | `UUID` | Nullable — null for BURN |
| `amount` | `DOUBLE PRECISION` | Number of tokens |
| `reference` | `TEXT` | Optional external reference (e.g. Paystack reference) |
| `status` | `TEXT` | `'SUCCESS'`, `'FAILED'` |
| `timestamp` | `TIMESTAMPTZ` | Auto-generated by Supabase (`DEFAULT now()`) |

**Transaction types created by this app:**
- `FARE` — Agent transfers tokens to a Student, or Student pays a Driver

#### `telemetry`
Stores GPS broadcasts from active Drivers. New rows are inserted every 5 seconds.

| Column | Type | Notes |
|---|---|---|
| `id` | `BIGSERIAL` | Auto-incrementing integer primary key |
| `driver_id` | `UUID` | Foreign key → `users.id` |
| `latitude` | `DOUBLE PRECISION` | Decimal latitude |
| `longitude` | `DOUBLE PRECISION` | Decimal longitude |
| `timestamp` | `TIMESTAMPTZ` | Auto-generated (`DEFAULT now()`) |

The Admin dashboard queries the most recent row per `driver_id` to place live map markers.

## Supabase Query Patterns Used in This App

All queries live exclusively in `lib/repositories/`. Views and ViewModels never call Supabase directly.

### SELECT — Reading a single row
```dart
// lib/repositories/wallet_repository.dart
final data = await _client
    .from('wallets')
    .select()                       // GET all columns
    .eq('owner_id', ownerId)        // WHERE owner_id = ownerId
    .single();                      // Expect exactly 1 row; throws if 0 or more

return WalletModel.fromJson(data);
```

### SELECT — Reading multiple rows
```dart
// lib/repositories/transaction_repository.dart
final data = await _client
    .from('transactions')
    .select()
    .eq('sender_wallet_id', walletId)
    .order('timestamp', ascending: false)  // ORDER BY timestamp DESC
    .limit(50);                            // LIMIT 50

return (data as List).map((row) => TransactionModel.fromJson(row)).toList();
```

### UPDATE — Modifying a row
```dart
// lib/repositories/wallet_repository.dart
final data = await _client
    .from('wallets')
    .update({'balance': newBalance})  // SET balance = newBalance
    .eq('id', walletId)              // WHERE id = walletId
    .select()                        // Return the updated row
    .single();

return WalletModel.fromJson(data);
```

### INSERT — Creating a new row
```dart
// lib/repositories/transaction_repository.dart
final data = await _client
    .from('transactions')
    .insert(payload)    // INSERT INTO transactions VALUES (...)
    .select()           // Also SELECT the new row (needed to get the auto-generated id)
    .single();

return TransactionModel.fromJson(data);
```

## Supabase Auth

### How Sign-In Works

```
User enters email + password in LoginWithEmailView
    ↓
AuthRepository.signIn() calls:
    _client.auth.signInWithPassword(email: email, password: password)
    ↓
Supabase verifies credentials against its Auth store
    ↓
Returns: AuthResponse { user: { id: 'uuid...' }, session: { access_token: 'eyJ...' } }
    ↓
Flutter SDK stores the access token in secure storage automatically
    ↓
Every subsequent Supabase query adds: Authorization: Bearer eyJ...
    ↓
Supabase RLS policies use auth.uid() to filter what this user can access
```

### Session Persistence

The Supabase Flutter SDK automatically:
- Stores the session in secure storage
- Refreshes the access token before it expires (tokens last 1 hour)
- Restores the session on app restart

The `SplashView` calls `authViewModel.restoreSession()` on every launch. If a valid session exists, the user is routed directly to their dashboard without re-logging in.

### QR Registration Flow

Agents and Drivers are created by the Admin on the web dashboard. The Admin generates a QR code containing temporary credentials. The user scans this QR on the `QrRegisterView` screen:

```
Admin generates QR in web dashboard
    │  QR contains JSON: { "e": "email", "p": "tempPass", "r": "Agent" }
    ▼
User scans QR with QrRegisterView (using mobile_scanner)
    │
    ▼
App calls: supabase.auth.signInWithPassword(email, tempPassword)
    │
    ▼
Sign-in succeeds → show "Set Your Password" dialog
    │  User enters their own password
    ▼
App calls: supabase.auth.updateUser(UserAttributes(password: newPassword))
    │
    ▼
User is routed to their dashboard
```

## Supabase Realtime — The Driver Boarding Stream

### What It Does

When a student pays a fare, a new `FARE` transaction is inserted into the `transactions` table. Supabase Realtime pushes this row over a WebSocket to any active Driver whose `Bus_Vault` wallet is the `receiver_wallet_id`.

The Driver's screen receives the event within ~200ms and:
1. Increments the passenger counter
2. Adds the transaction to the fare list
3. Sets `isFlashing = true` → the screen flashes green
4. Plays the boarding chime (when audio asset is available)
5. Resets `isFlashing = false` after 1.5 seconds

### The Stream Code

```dart
// lib/repositories/transaction_repository.dart

Stream<TransactionModel> watchBoardingEvents(String driverWalletId) {
  return _client
      .from('transactions')
      .stream(primaryKey: ['id'])
      .eq('receiver_wallet_id', driverWalletId)  // Only this driver's fares
      .order('timestamp', ascending: false)
      .limit(1)
      .map((rows) {
        if (rows.isEmpty) return null;
        return TransactionModel.fromJson(rows.first);
      })
      .where((tx) => tx != null)
      .cast<TransactionModel>();
}
```

### Setup Required

Supabase Realtime must be enabled for the `transactions` table. Run this SQL once in your Supabase SQL Editor:

```sql
ALTER PUBLICATION supabase_realtime ADD TABLE transactions;
```

To verify it's enabled:
```sql
SELECT tablename FROM pg_publication_tables
WHERE pubname = 'supabase_realtime' AND tablename = 'transactions';
```

If the `transactions` table already appears there, Realtime is active. The error `42710: relation is already member of publication` means it was already enabled — this is fine.

### Subscription Lifecycle

The `DriverDashboardViewModel` manages the subscription:
- **On mount** (`initializeDashboard()` is called): stream subscription is created
- **On logout / dispose** (`_cleanup()` is called by Riverpod's `ref.onDispose()`): subscription is cancelled

```dart
// lib/viewmodels/driver_dashboard_viewmodel.dart

@override
DriverDashboardState build() {
  ref.onDispose(_cleanup);  // Riverpod calls this automatically on dispose
  return const DriverDashboardState();
}

void _cleanup() {
  _gpsTimer?.cancel();
  _boardingSubscription?.cancel();  // Cancels the WebSocket stream
  _flashResetTimer?.cancel();
}
```

## GPS Telemetry

### Flow

Every 5 seconds while a Driver is on their dashboard:

```
Timer.periodic(5 seconds) fires
    ↓
LocationService.getCurrentPosition()
    │  Checks permission → Requests if needed → Gets GPS coordinates
    ▼
TelemetryRepository.broadcastLocation(driverId, latitude, longitude)
    ↓
Supabase INSERT into telemetry table
    ↓
Admin dashboard queries latest row per driver_id for fleet map
```

### Error Handling

If location permission is denied or GPS is unavailable, the error is caught silently. The `isGpsActive` state flag is set to `false`, making the GPS indicator in the Driver's UI show as inactive. The app does **not** crash.

```dart
// lib/viewmodels/driver_dashboard_viewmodel.dart

Future<void> _broadcastGpsLocation(String driverId) async {
  try {
    final position = await locationService.getCurrentPosition();
    if (position == null) { ... return; }
    await telemetryRepo.broadcastLocation(...);
  } catch (e) {
    // Log the error but DO NOT rethrow — GPS failure must never crash the app
    logger.w('[DriverViewModel] GPS broadcast error (non-fatal): $e');
  }
}
```

## Row Level Security (RLS)

Supabase blocks all table access by default. RLS policies define what each authenticated user is allowed to do.

### Development Policies

Run these in your SQL Editor to enable access for all authenticated users during development:

```sql
-- users: read access
CREATE POLICY "Authenticated can read users" ON users
  FOR SELECT USING (auth.role() = 'authenticated');

-- wallets: read + update
CREATE POLICY "Authenticated can read wallets" ON wallets
  FOR SELECT USING (auth.role() = 'authenticated');

CREATE POLICY "Authenticated can update wallets" ON wallets
  FOR UPDATE USING (auth.role() = 'authenticated');

-- transactions: read + insert
CREATE POLICY "Authenticated can read transactions" ON transactions
  FOR SELECT USING (auth.role() = 'authenticated');

CREATE POLICY "Authenticated can insert transactions" ON transactions
  FOR INSERT WITH CHECK (auth.role() = 'authenticated');

-- telemetry: insert only
CREATE POLICY "Authenticated can insert telemetry" ON telemetry
  FOR INSERT WITH CHECK (auth.role() = 'authenticated');
```

> **Before any real-world deployment**, restrict these policies to per-user ownership rules (e.g. "Agent can only update their own wallet").
